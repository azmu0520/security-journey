# 1.3 Analyzing Algorithms - Complete Deep Dive

## 🎯 Core Philosophy

**Algorithm analysis** is the systematic study of how much time and space an algorithm requires as a function of input size. It's not about measuring exact seconds—it's about understanding **growth patterns** and **scalability**.

---

## 📊 The Three Pillars of Analysis

### 1. **Correctness**

Does the algorithm solve the problem for all valid inputs?

### 2. **Efficiency**

How do time and space requirements grow with input size?

### 3. **Simplicity**

Is the algorithm understandable and maintainable?

> **Interview Insight:** Companies care most about correctness first, then efficiency. A correct O(n²) solution beats a buggy O(n) solution every time.

---

## 🔍 Types of Analysis

### 1. **Best Case Analysis (Big Omega Ω)**

**Definition:** Minimum time/space needed for any input of size n

**Example: Linear Search**

```python
def linear_search(arr, target):
    for i in range(len(arr)):
        if arr[i] == target:
            return i
    return -1

# Best case: target is first element → Ω(1)
# Only 1 comparison needed
```

**When to mention in interviews:**

- When the algorithm has significantly different performance paths
- When discussing optimistic scenarios
- When comparing algorithms with different best cases

---

### 2. **Average Case Analysis (Big Theta Θ)**

**Definition:** Expected time/space over all possible inputs

**Example: Quick Sort**

```python
def quick_sort(arr):
    if len(arr) <= 1:
        return arr

    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]

    return quick_sort(left) + middle + quick_sort(right)

# Average case: balanced partitions → Θ(n log n)
# Worst case: already sorted → O(n²)
```

**Calculating Average Case:**

- Consider probability distribution of inputs
- Often requires mathematical expectation
- Most useful for randomized algorithms

---

### 3. **Worst Case Analysis (Big O)**

**Definition:** Maximum time/space for any input of size n

**Example: Bubble Sort**

```python
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        for j in range(n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
    return arr

# Worst case: reverse sorted → O(n²)
# Must compare every pair
```

**Why focus on worst case?**

- Provides **guarantees** for performance
- Most conservative estimate
- Industry standard for analysis
- Critical for real-time systems

> **Interview Gold:** "I always analyze worst case first because it guarantees my algorithm won't exceed that time, which is crucial for production systems where consistency matters."

## 🔄 Analyzing Iterative Algorithms

### Step-by-Step Method

**1. Identify the input size (n)**
**2. Count operations as a function of n**
**3. Find the dominant term**
**4. Drop constants and lower-order terms**

---

### Example 1: Single Loop

```python
def sum_array(arr):
    total = 0                    # O(1) - one assignment
    for num in arr:              # O(n) - loop n times
        total += num             # O(1) - one addition per iteration
    return total                 # O(1) - one return

# Analysis:
# - Setup: O(1)
# - Loop: n iterations × O(1) per iteration = O(n)
# - Cleanup: O(1)
# Total: O(1) + O(n) + O(1) = O(n)
```

---

### Example 2: Nested Loops (Same Input)

```python
def print_pairs(arr):
    for i in range(len(arr)):          # n iterations
        for j in range(len(arr)):      # n iterations each
            print(arr[i], arr[j])      # O(1)

# Analysis:
# Outer loop: n times
# Inner loop: n times (for each outer iteration)
# Work per iteration: O(1)
# Total: n × n × O(1) = O(n²)
```

---

### Example 3: Nested Loops (Different Inputs)

```python
def print_combinations(arr1, arr2):
    for x in arr1:                # a iterations (where a = len(arr1))
        for y in arr2:            # b iterations (where b = len(arr2))
            print(x, y)           # O(1)

# Analysis:
# Total: a × b × O(1) = O(a × b)
# Cannot simplify to O(n²) - different inputs!
```

> **Common Interview Mistake:** Don't assume all nested loops are O(n²). Always check if they iterate over the same or different inputs.

---

### Example 4: Dependent Nested Loops

```python
def print_triangular(arr):
    for i in range(len(arr)):           # n iterations
        for j in range(i):              # 0, 1, 2, ..., n-1 iterations
            print(arr[i], arr[j])

# Analysis:
# Iterations: 0 + 1 + 2 + ... + (n-1)
# Sum = n(n-1)/2 = (n² - n)/2
# Drop constants and lower terms: O(n²)
```

**Mathematical insight:**

```
Iterations = Σ(i) from i=0 to n-1
           = 0 + 1 + 2 + ... + (n-1)
           = n(n-1)/2
           = n²/2 - n/2
           ≈ O(n²)  (drop constants and lower terms)
```

---

### Example 5: Sequential Loops

```python
def process_data(arr):
    # First pass: find max
    max_val = arr[0]
    for num in arr:                    # O(n)
        if num > max_val:
            max_val = num

    # Second pass: find min
    min_val = arr[0]
    for num in arr:                    # O(n)
        if num < min_val:
            min_val = num

    # Third pass: sum
    total = 0
    for num in arr:                    # O(n)
        total += num

    return max_val, min_val, total

# Analysis:
# Three sequential loops: O(n) + O(n) + O(n)
# Total: O(3n) = O(n)
# Sequential loops ADD
```

---

### Example 6: Logarithmic Loop

```python
def binary_search_iterative(arr, target):
    left, right = 0, len(arr) - 1

    while left <= right:               # How many iterations?
        mid = (left + right) // 2

        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1             # Cut search space in half
        else:
            right = mid - 1            # Cut search space in half

# Analysis:
# Each iteration cuts search space in half
# n → n/2 → n/4 → n/8 → ... → 1
# Number of divisions: log₂(n)
# Total: O(log n)
```

**Why is it logarithmic?**

```
Start: n elements
After 1 iteration: n/2 elements
After 2 iterations: n/4 elements
After k iterations: n/(2^k) elements

When does it stop? When n/(2^k) = 1
Solving: n = 2^k
Therefore: k = log₂(n)
```

---

### Example 7: Loop with Exponential Growth

```python
def exponential_loop(n):
    i = 1
    while i < n:
        print(i)
        i *= 2                # Double each time

# Analysis:
# Iterations: i = 1, 2, 4, 8, 16, ..., n
# Number of doublings to reach n: log₂(n)
# Total: O(log n)
```

## 🌳 Analyzing Recursive Algorithms

### Method 1: Recursion Tree Method

**Visualize the recursive calls as a tree**

**Example: Naive Fibonacci**

```python
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n-1) + fibonacci(n-2)
```

**Recursion Tree for fib(5):**

```
                    fib(5)
                   /      \
              fib(4)      fib(3)
             /     \      /     \
        fib(3)   fib(2) fib(2) fib(1)
        /   \    /   \  /   \
    fib(2) fib(1) ...  (continues)
```

**Analysis:**

- **Depth:** n levels
- **Branching:** Each node has 2 children
- **Work per node:** O(1)
- **Total nodes:** approximately 2^n
- **Time Complexity:** O(2^n)

---

### Method 2: Recurrence Relations

**Write the recursive time complexity as an equation**

#### Example 1: Binary Search (Divide by 2)

```python
def binary_search(arr, target, left, right):
    if left > right:
        return -1

    mid = (left + right) // 2

    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        return binary_search(arr, target, mid + 1, right)
    else:
        return binary_search(arr, target, left, mid - 1)
```

**Recurrence Relation:**

```
T(n) = T(n/2) + O(1)

Where:
- T(n/2): time for one recursive call on half the input
- O(1): constant work (comparison, arithmetic)
```

**Solution:**

```
T(n) = T(n/2) + c
     = T(n/4) + c + c
     = T(n/8) + c + c + c
     = T(1) + c × log₂(n)
     = O(log n)
```

---

#### Example 2: Merge Sort (Divide and Conquer)

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr

    mid = len(arr) // 2
    left = merge_sort(arr[:mid])      # T(n/2)
    right = merge_sort(arr[mid:])     # T(n/2)

    return merge(left, right)         # O(n)

def merge(left, right):
    result = []
    i = j = 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1

    result.extend(left[i:])
    result.extend(right[j:])
    return result
```

**Recurrence Relation:**

```
T(n) = 2T(n/2) + O(n)

Where:
- 2T(n/2): two recursive calls on halves
- O(n): linear work to merge
```

**Recursion Tree:**

```
Level 0:           [n]                     = n work
Level 1:       [n/2]  [n/2]               = n work
Level 2:     [n/4][n/4][n/4][n/4]         = n work
...
Level log n: [1][1]...[1] (n times)       = n work

Total levels: log₂(n) + 1
Work per level: O(n)
Total: O(n log n)
```

---

### Method 3: Master Theorem

**For recurrences of the form: T(n) = aT(n/b) + f(n)**

Where:

- **a** = number of recursive calls
- **b** = factor by which input is divided
- **f(n)** = work done outside recursion

**Three Cases:**

**Case 1:** If f(n) = O(n^c) where c < log_b(a)

- **Result:** T(n) = Θ(n^(log_b(a)))

**Case 2:** If f(n) = Θ(n^c × log^k(n)) where c = log_b(a)

- **Result:** T(n) = Θ(n^c × log^(k+1)(n))

**Case 3:** If f(n) = Ω(n^c) where c > log_b(a)

- **Result:** T(n) = Θ(f(n))

---

**Examples:**

**1. Binary Search: T(n) = T(n/2) + O(1)**

```
a = 1, b = 2, f(n) = O(1) = O(n⁰)
log_b(a) = log₂(1) = 0

Case 2: c = log_b(a)
Result: T(n) = Θ(log n)
```

**2. Merge Sort: T(n) = 2T(n/2) + O(n)**

```
a = 2, b = 2, f(n) = O(n) = O(n¹)
log_b(a) = log₂(2) = 1

Case 2: c = log_b(a)
Result: T(n) = Θ(n log n)
```

**3. Karatsuba Multiplication: T(n) = 3T(n/2) + O(n)**

```
a = 3, b = 2, f(n) = O(n)
log_b(a) = log₂(3) ≈ 1.585

Case 1: f(n) = O(n¹) and 1 < 1.585
Result: T(n) = Θ(n^1.585)
```

## 📐 Hidden Complexity Traps

### Trap 1: String Concatenation

```python
def concatenate_strings(arr):
    result = ""
    for s in arr:
        result += s    # O(len(result)) in most languages!
    return result

# Analysis:
# First iteration: copy 0 chars
# Second iteration: copy len(arr[0]) chars
# Third iteration: copy len(arr[0]) + len(arr[1]) chars
# ...
# Total: O(n²) for n strings!
```

**Better approach:**

```python
def concatenate_strings_optimized(arr):
    return "".join(arr)    # O(n) - single allocation

# join() allocates once and copies once
```

---

### Trap 2: Array Slicing

```python
def process_slices(arr):
    for i in range(len(arr)):
        subarr = arr[i:]    # O(n) - creates new array!
        print(subarr)

# Analysis:
# First iteration: copy n elements
# Second iteration: copy n-1 elements
# ...
# Total: O(n²)
```

---

### Trap 3: List Insertion at Beginning

```python
def insert_at_front(arr, values):
    result = []
    for val in values:
        result.insert(0, val)    # O(n) - shifts all elements!

# Total: O(n²) where n = len(values)
```

**Better approach:**

```python
def insert_at_front_optimized(arr, values):
    result = []
    for val in values:
        result.append(val)    # O(1) amortized
    return result[::-1]       # O(n) reverse at end

# Total: O(n)
```

---

### Trap 4: Dictionary Operations in Loops

```python
def count_frequencies(arr):
    freq = {}
    for item in arr:
        if item in freq:           # O(1) average, O(n) worst
            freq[item] += 1
        else:
            freq[item] = 1

# Average: O(n)
# Worst (many collisions): O(n²)
```

## 🎯 Best vs Average vs Worst Case

### Quick Sort Example

```python
def quick_sort(arr):
    if len(arr) <= 1:
        return arr

    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]

    return quick_sort(left) + middle + quick_sort(right)
```

**Best Case: Θ(n log n)**

- Pivot always divides array into equal halves
- Perfectly balanced partitions
- Occurs with random data or good pivot selection

**Average Case: Θ(n log n)**

- Most partitions are reasonably balanced
- Expected behavior with random input
- Proven mathematically

**Worst Case: O(n²)**

- Pivot is always smallest or largest element
- Unbalanced partitions (n-1 and 0)
- Occurs with already sorted data (naive pivot selection)

> **Interview Tip:** "Quick Sort is O(n²) worst case, but we use it in practice because the average case is O(n log n) and it has better constants than Merge Sort. We can guarantee O(n log n) by using median-of-three pivot selection or switching to Heap Sort for bad partitions."

## 💡 Real-World Performance Considerations

### 1. **Cache Locality**

**Arrays vs Linked Lists:**

```python
# Array: O(n) iteration
for i in range(len(arr)):
    process(arr[i])

# Linked List: Also O(n) iteration
current = head
while current:
    process(current.val)
    current = current.next

# Both O(n), but array is MUCH faster in practice!
# Why? Cache locality - array elements are contiguous in memory
```

---

### 2. **Hidden Constants Matter**

```python
# Algorithm A: 100n operations (O(n))
def algorithm_a(arr):
    for _ in range(100):
        for item in arr:
            # simple operation

# Algorithm B: 0.01n² operations (O(n²))
def algorithm_b(arr):
    for i in range(len(arr)):
        for j in range(i):
            if i % 100 == 0 and j % 100 == 0:
                # simple operation

# For n < 10,000: Algorithm B is faster!
# For n > 10,000: Algorithm A wins
```

---

### 3. **Amortized Analysis**

**Dynamic Array Resize:**

```python
class DynamicArray:
    def __init__(self):
        self.arr = [None] * 1
        self.size = 0
        self.capacity = 1

    def append(self, item):
        if self.size == self.capacity:
            # Double capacity
            new_arr = [None] * (self.capacity * 2)
            for i in range(self.size):
                new_arr[i] = self.arr[i]    # O(n) copy
            self.arr = new_arr
            self.capacity *= 2

        self.arr[self.size] = item
        self.size += 1

# Single append:
# - Best case: O(1)
# - Worst case: O(n) when resizing
# - Amortized: O(1)

# Why amortized O(1)?
# Resizes happen at n = 1, 2, 4, 8, 16, ...
# Total cost for n appends:
# 1 + 2 + 4 + 8 + ... + n = 2n
# Average cost per append: 2n/n = O(1)
```

## 🎤 Top Interview Questions & Model Answers

### Q1: How do you analyze the time complexity of a recursive algorithm?

**Perfect Answer:**

> "I use three main approaches:
>
> **1. Recurrence Relations:** I write T(n) as a function of T(smaller problems) plus the work done at this level. For example, merge sort is T(n) = 2T(n/2) + O(n).
>
> **2. Recursion Tree:** I visualize the recursive calls. Each level shows how many calls happen and how much work each does. The tree's depth times work per level gives total complexity.
>
> **3. Master Theorem:** For divide-and-conquer recurrences T(n) = aT(n/b) + f(n), I identify a, b, and f(n), then apply the appropriate case.
>
> I prefer the recursion tree for intuition, but the Master Theorem is fastest for standard patterns."

---

### Q2: What's the Master Theorem and when do you use it?

**Perfect Answer:**

> "The Master Theorem solves recurrences of the form T(n) = aT(n/b) + f(n), where:
>
> - a = number of recursive calls
> - b = factor by which we divide the input
> - f(n) = work done outside recursion
>
> It has three cases based on comparing f(n) to n^(log_b(a)):
>
> **Case 1:** If f(n) is polynomially smaller, recursion dominates → T(n) = Θ(n^(log_b(a)))
> **Case 2:** If they're equal, both contribute equally → T(n) = Θ(n^c × log n)
> **Case 3:** If f(n) is polynomially larger, non-recursive work dominates → T(n) = Θ(f(n))
>
> I use it for divide-and-conquer algorithms like merge sort (Case 2: O(n log n)) and binary search (Case 2: O(log n)). It's much faster than manually expanding the recurrence."

---

### Q3: Explain the difference between best, average, and worst case analysis.

**Perfect Answer:**

> "These describe how an algorithm performs under different input conditions:
>
> **Best Case (Ω):** Minimum time for the most favorable input. Example: linear search finds the target in the first position → Ω(1).
>
> **Average Case (Θ):** Expected time over all possible inputs, weighted by probability. Requires knowing input distribution. Example: linear search on average checks n/2 elements → Θ(n).
>
> **Worst Case (O):** Maximum time for the most unfavorable input. This is what Big O typically describes. Example: linear search checks all n elements → O(n).
>
> In interviews, I focus on worst case because it provides guarantees. However, I'll mention average case for algorithms like quick sort, where average (O(n log n)) differs significantly from worst case (O(n²))."

---

### Q4: How do you analyze loops with logarithmic behavior?

**Perfect Answer:**

> "Logarithmic loops either divide or multiply by a constant factor each iteration.
>
> **Halving pattern:**
>
> ```python
> while i > 0:
>     i //= 2
> ```
>
> Loop runs log₂(n) times because i = n → n/2 → n/4 → ... → 1
>
> **Doubling pattern:**
>
> ```python
> while i < n:
>     i *= 2
> ```
>
> Same logic: i = 1 → 2 → 4 → 8 → ... → n takes log₂(n) steps.
>
> The key insight: if you're repeatedly dividing or multiplying by a constant factor to reach your target, you get logarithmic complexity. This is why binary search is O(log n) — we halve the search space each time."

---

### Q5: What are some hidden performance traps in common operations?

**Perfect Answer:**

> "Several operations look O(1) but are actually O(n):
>
> **1. String concatenation:** In Python/Java, `result += string` copies the entire result string. Doing this in a loop is O(n²). Use `''.join()` or StringBuilder instead.
>
> **2. Array slicing:** `arr[i:]` creates a new array by copying elements — that's O(n), not O(1).
>
> **3. List insert at beginning:** `list.insert(0, x)` shifts all elements right — O(n). Use deque or append + reverse.
>
> **4. Dictionary in worst case:** Hash table operations are O(1) average but O(n) worst case with many collisions.
>
> In interviews, I always consider the actual cost of built-in operations, not just the loop structure. Real performance depends on both."

---

### Q6: How do you handle algorithms with multiple different-sized inputs?

**Perfect Answer:**

> "I use different variables for each input size. For example:
>
> ```python
> def find_common(arr1, arr2):
>     result = []
>     for x in arr1:         # O(a) where a = len(arr1)
>         for y in arr2:     # O(b) where b = len(arr2)
>             if x == y:
>                 result.append(x)
>     return result
> ```
>
> This is O(a × b), not O(n²)! I can't simplify further without knowing the relationship between a and b.
>
> However, I can optimize: sorting arr2 and using binary search gives O(a log b + b log b). Using a hash set: O(a + b). The best approach depends on the relative sizes and whether I can use extra space."

---

### Q7: What's amortized analysis and when is it useful?

**Perfect Answer:**

> "Amortized analysis finds the average cost per operation over a sequence, even when individual operations vary in cost.
>
> **Classic example:** Dynamic array append
>
> - Most appends are O(1) — just add to the end
> - Occasional appends are O(n) — when we need to resize
> - Amortized: O(1) — because resizes are rare (exponentially spaced)
>
> **Calculation:** For n appends, resizes happen at sizes 1, 2, 4, 8, ..., n
>
> - Total copy cost: 1 + 2 + 4 + ... + n ≈ 2n
> - Average per append: 2n/n = O(1)
>
> I use amortized analysis when an algorithm has occasional expensive operations that are infrequent enough not to dominate. It's different from average-case analysis — amortized is about operation sequences, while average-case is about input probability."

## 🚨 Common Analysis Mistakes

### Mistake 1: Assuming All Nested Loops are O(n²)

```python
# This is O(n log n), NOT O(n²)
for i in range(n):
    j = 1
    while j < n:
        j *= 2        # Doubling → log n iterations

# Outer: n, Inner: log n → n × log n
```

---

### Mistake 2: Forgetting Hidden Operations

```python
# This is O(n²), not O(n)!
def reverse_words(words):
    result = ""
    for word in words:
        result = word + " " + result    # String copy: O(len(result))

# Each concatenation copies the entire result string
```

---

### Mistake 3: Wrong Variable for Different Inputs

```python
# WRONG: "This is O(n²)"
# RIGHT: "This is O(a × b)"
```

## 💡 Pro Analysis Tips for Interviews

1. **Start with the input size:** "Let n be the length of the array..."

2. **Walk through the code systematically:** Don't just give the answer, show your process

3. **Count operations, not lines:** Multiple operations per line still count

4. **Check for hidden complexity:** Slicing, concatenation, hash collisions

5. **Use concrete examples:** "For n=8, this takes 3 iterations because..."

6. **Draw pictures:** "Recursion trees and loop iteration diagrams clarify thinking"

7. **State both time and space:** "This is O(n) time and O(1) space"

8. **Draw pictures:** "I can reduce time from O(n²) to O(n log n) by sorting first"
